# AGENTS.md

`pi-stick` is a Linux CLI platform for isolated Docker project workspaces and extensible single- or multi-agent tasks.

## Layout

- `pistick`, `pistick-dev`, `src/` — Host CLI (`pistick` command, `pi-stick` package). Runs directly on Node 24.12+ and bundles with Bun. **Use Node built-ins only** (no npm runtime dependencies). Uncompiled `./pistick` (without `PI_STICK_HOME`), `./pistick-dev`, `--dev`, or `PI_STICK_DEV=1` runs in isolated dev mode (`~/pi-stick-dev`, `~/pi-stick-dev/settings.json`, `pi-stick:dev`, live checkout assets).
  - `src/cli.ts`, `src/main.ts` — Thin executable wrapper and CLI dispatcher.
  - `src/platform.ts` — Paths, settings, `flock` helpers, process helpers.
  - `src/workspace.ts` — Local Docker project workspaces (`create project`, discovery).
  - `src/actions.ts` — Two-tier trusted action loader/validator, scaffolding (`create action`), and host hooks (`prepare`/`after`).
  - `src/tasks.ts` — Per-task isolated workspace, base Compose validation/materialization, lifecycle (`up`/`start`/`stop`/`down`), diff capture, and multiplexed host-broker RPC (`exec`, `logs`, `ps`, `restart`, `check_clean`).
  - `src/runs.ts` — Per-run locks, concurrent detached workers, `run`/`runs`/`follow`/`resume`/`continue`/`containers stop`/`diff`/`cleanup`.
  - `src/agent-rpc.ts` — Host-side JSONL RPC bridge to the ephemeral agent container.
  - `src/system.ts` — Ephemeral container args, multi-provider Pi model/token resolution, offline runtime probe, `doctor`, and `containers build`.
- `agent-runtime.ts`, `Dockerfile`, `.dockerignore` — Ephemeral containerized agent runtime (runs inside Docker with `@earendil-works/*` dependencies, native file tools, Codemode, static stages, and dynamic parallel `delegate`).
- `runtime-tools/` — Container tool implementations; `agent-runtime.ts` supplies runtime policies and registers tools.
- `action.schema.json` — JSON Schema for user-authored `action.json` manifests.
- `project-template/` — Scaffold copied verbatim into new project workspaces.
- `scripts/` — Release staging (`stage-release.sh`), Linux binary/npm packaging (`build-linux.sh`, `pack-npm.sh`), interactive installers (`install.sh`, `install-dev.sh`), and Biome plugins.
- `test/cli.test.ts` — CLI and offline `agent-runtime.ts` test suite (`PI_STICK_TEST_BINARY` overrides the binary under test).
- `docs/plan.md` — High-level architecture and roadmap.

## Verification

- `npm run check` — Biome lint/format check (warnings are errors) and `tsc --noEmit`.
- `npm run lint -- --write` — Apply safe Biome fixes.
- `npm test` — Run `node --test test/*.test.ts`.
- `npm run build:binary` / `npm run pack:npm` — Build release artifacts (uses Bun pinned in `mise.toml`).

Run `npm run check` and `npm test` after changes.

## Conventions

- Use Hindsight MCP with the `pi-stick` bank to recall relevant project context and retain decisions and their rationale; never store secrets.

- TypeScript compiles with `strict`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, and `allowImportingTsExtensions`: keep explicit `.ts` import extensions and avoid non-erasable TS syntax (enums, parameter properties).
- Keep `package.json` `"private": true`; public npm manifests are generated by `scripts/pack-npm.sh`.
- If you add, rename, or remove shipped runtime files, update `scripts/stage-release.sh` and `.dockerignore` as needed.
- Keep untrusted repo content isolated: never evaluate repo-supplied paths as shell code on the host, never auto-load actions or hooks from `repo/`, never expose a Docker socket inside containers, and keep credentials strictly on stdin (never in build contexts, argv, env, Git, or logs).
